**TDD Harms Architecture** summarizes clean-code-style guidance from [TDD Harms Architecture](https://blog.cleancoder.com/uncle-bob/2017/03/03/TDD-Harms-Architecture.html).

The article argues against the claim that TDD damages architecture. TDD does not replace
architectural thinking; it supplies feedback while design decisions are still required.

## Style Guidance

- Use TDD as a design feedback loop, not as an excuse to ignore architecture.
- Keep architectural boundaries visible as tests drive implementation.
- If tests produce poor structure, inspect the design skill and testing approach rather than blaming the cycle alone.
